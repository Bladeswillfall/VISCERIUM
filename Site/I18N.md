# Internationalisation readiness

VISCERIUM is currently published in English. This workstream makes the Codex safe to localise later without creating an ongoing translation obligation now.

## Contract

- English remains the canonical and only required published locale until localisation is explicitly commissioned.
- Use BCP 47 language tags. The default public locale is `en-GB`; feed or machine formats may use the shorter `en` form where that format expects it.
- Page language must be exposed in the document language metadata.
- User-interface copy owned by VISCERIUM components should move behind a small locale dictionary instead of being duplicated as string literals.
- Dates, numbers and list formatting should use locale-aware platform APIs rather than English-only string construction.
- New layout CSS should prefer logical properties (`inline-start`, `inline-end`, `margin-inline`, etc.) when direction matters.
- Canonical lore identity must not depend on a translated display title.
- Future translated routes must be able to declare alternate language URLs without changing the canonical lore source in `Vault/Lore/`.
- Mixed-language source material should preserve explicit language metadata where known. Fictional terminology does not need a fabricated real-world language tag.

## Non-goals

- Translating the current Codex.
- Adding locale folders before a second locale exists.
- Duplicating canonical lore in multiple vault trees.
- Using machine translation as canonical content.

## First implementation steps

1. Centralise the default locale in `site.config.mjs`.
2. Make shared UI labels retrievable through a locale dictionary.
3. Add regression tests for the default language and dictionary fallback.
4. Only enable locale-prefixed routing when a second published locale is approved.
