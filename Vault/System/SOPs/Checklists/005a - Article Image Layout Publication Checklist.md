# Article Image Layout Publication Checklist

> **Parent guide:** [[Article Image Layout]]

## Image purpose

- [ ] Every image supports identification, atmosphere, explanation, navigation, or visual rhythm.
- [ ] Decorative images are not presented as factual evidence.
- [ ] Diagrams, maps, and tables receive uninterrupted viewing space.

## Accessibility

- [ ] Every informative image has useful alternative text.
- [ ] Alternative text describes relevant visible content rather than repeating the filename.
- [ ] Layout flags do not leak into alternative text.
- [ ] Decorative treatment does not remove necessary text information.

## Layout

- [ ] Left, right, centre, wide, full, and numeric widths are used only where appropriate.
- [ ] Wrapped text does not become uncomfortably narrow.
- [ ] Shape wrapping is used only with meaningful transparency.
- [ ] Images do not overlap headings, callouts, tables, rules, or adjacent columns.
- [ ] Source reading order remains logical without the visual layout.

## Responsive behaviour

- [ ] Columns stack in a sensible order.
- [ ] Floated images become readable centred blocks on narrow screens.
- [ ] Image width never exceeds its container.
- [ ] The article remains understandable when an image fails to load.

## Technical result

- [ ] Raster repository artwork uses the required managed format.
- [ ] Obsidian and the public Codex show materially consistent layout.
- [ ] A representative build reports no image or layout error.

## Decision

- [ ] **Publication ready**
- [ ] **Not ready** - blocking reason recorded.
