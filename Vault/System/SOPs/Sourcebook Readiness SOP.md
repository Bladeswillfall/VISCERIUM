# Sourcebook Readiness SOP

> **Use this SOP when:** Canon may support a sourcebook, gazetteer, setting guide, or adventure product.
>
> **Result:** A future writer can make the next product decision from confirmed canon.
>
> **First action:** Define one subject or product scope.

Follow [[Documentation Writing Standard]] for operational wording.

## Purpose

Keep important canon reusable for a future writer.

Do not turn worldbuilding into a completion exercise.

> **Core rule:** Record useful connections. Do not model the world only to make it complete.

## Before you start

1. Define the subject or product scope.
2. Open the most authoritative notes for that scope.
3. Identify the next decision that a future writer must make.
4. Do not audit the complete setting without a product reason.

> **Why:** A narrow product scope separates important gaps from harmless unknown detail.

## Readiness test

For an important region or faction, check the questions that apply.

### Place and movement

- Where is the subject?
- Which places connect to it?
- How do people enter, cross, and leave the area?
- Which fauna, flora, fungi, and hostile entities can plausibly occur there?

### People and systems

- Who lives or operates there?
- What sustains ordinary life?
- Who holds formal and practical authority?
- Which resources, goods, services, and institutions matter?

### History and story pressure

- Which historical events still affect present behaviour?
- What does an outsider notice or misunderstand?
- Which tensions naturally create stories?

A future product can add presentation, examples, tables, and game-system adapters later.

The Codex should preserve the world facts that those products need.

## Develop important everyday-world facts

1. Select one important location or faction.
2. Ask only questions that affect a current creative decision.
3. Record distinctive answers in the authoritative note or a linked note.
4. Keep ordinary assumptions implicit when they create no setting consequence.
5. Create a note only when several canon sources need the concept independently.

### Living here

Use these prompts when ordinary life matters:

- What do people eat, wear, and live in?
- What work sustains households and settlements?
- How do people travel locally?
- What happens when a person cannot work?

Use these prompts when social development matters:

- What does childhood, training, or education involve?
- What do people do for leisure, celebration, or mourning?

### Society

Use these prompts when authority or social structure matters:

- Who has authority in daily life?
- Who controls wealth, land, tools, or access?
- Which laws, customs, or taboos change ordinary behaviour?
- Which institutions provide help, permission, justice, credit, shelter, or information?
- Where is social hierarchy visible in ordinary interactions?

### Material world

Use these prompts when production and trade matter:

- What is produced locally?
- What must arrive from elsewhere?
- What is unusually common, scarce, expensive, or restricted?
- Which technologies, materials, or supernatural practices change ordinary life?
- Which goods or services attract outsiders?

### Movement

Use these prompts when travel matters:

- Why do residents leave?
- Why do outsiders arrive?
- What does meaningful local travel require?
- Which roads, rivers, passes, ports, or routes shape movement?
- What changes with season, war, weather, or Myrkild activity?

## Add deeper location structure

Use this procedure when a current decision needs more structured location data.

### Select the modules

1. Open the current `type: location` note.
2. Press **Ctrl/Cmd + P**.
3. Run **Templater: Insert template**.
4. Select `Add Location Fields`.
5. Select only modules that answer the current question.

### Enter the values

1. Enter confirmed values.
2. Leave unknown optional properties absent.

Use `location_kind` for a broad initial classification:

- `region`
- `settlement`
- `wilderness`
- `route`
- `site`

| Module | Questions it supports |
| --- | --- |
| **Settlement** | Scale, population band, authority, economy, services, and defences. |
| **Wilderness** | Terrain, climate, resources, travel, and environmental hazards. |
| **Site / ruin** | Origin, condition, current use, access, and notable features. |
| **Route** | Connected places, traffic, conditions, seasonal change, and recurring dangers. |

A location can use more than one module when the subject overlaps categories.

## Keep Lore and Storyteller data separate

Use Lore and location properties for world facts.

Use Storyteller properties for short story-facing consequences.

Follow [[Storyteller View SOP]] when you add Storyteller data.

Do not duplicate one sentence across both layers only to fill fields.

## Decide whether a concept needs its own note

1. Check whether several unrelated notes use the concept in important ways.
2. Check whether its history, rules, membership, use, or consequences matter independently.
3. Check whether one source note would prevent conflicting copies.
4. Check whether creators need to navigate to it or add structured relationships.
5. Create a separate note when these benefits justify its maintenance cost.

Do not create a formal entity type only because a new noun appears.

A local custom can remain inside one settlement note.

A tradition shared across several nations can justify its own note.

## Run a product-scoped audit

Do not use percentage completion for the full setting.

### Set the scope

1. Name one hypothetical product.
2. Define its era.
3. Define its geographic or faction scope.

### Record the findings

1. List the world functions that the product needs.
2. Inspect only canon that supports those functions.
3. Give each finding one readiness label.
4. Create a task only when you decide to fill the gap now.

| Label | Meaning |
| --- | --- |
| **Strong** | Enough confirmed material exists. |
| **Thin** | A writer must invent important connecting facts. |
| **Missing but valuable** | The absence weakens the proposed product. |
| **Safe to invent later** | Later presentation can add the detail without changing canon. |

Example scope:

> **The Okse Dominion: CITADEL regional sourcebook**

Use the CITADEL Okse Dominion as the first stress test.

Use a society with different structures, such as Askalia, for a later comparison.

## Verification checklist

Use [[Checklists/011a - Sourcebook Reference Readiness Checklist|Sourcebook Reference Readiness Checklist]] after the product-scoped audit.

## Check the result

1. Confirm that a future writer can understand how the subject functions.
2. Confirm that the writer can trace important places, people, resources, movement, and authority.
3. Confirm that the next decision needs no missing foundational fact.
4. Confirm that the audit did not turn optional detail into automatic work debt.

## Stop condition

Stop when a future writer can make the next creative decision from confirmed canon.

More metadata does not automatically make the source material more useful.
